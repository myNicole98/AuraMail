## Highlights

- AuraMail keeps its secrets in its own store now instead of the system keyring, and migrates the credential it already holds on the first launch; the store is a `secrets.json` file in the app data folder, protected by your user account rather than by the keyring's per-app approval

## Fixes

- macOS no longer asks for your login password after every update: the stored credentials are no longer tied to the app's code signature, which changes with each build
- A keyring that is still locked when the app starts no longer leaves accounts unable to sync with a "secret store unavailable" error
- A credential the app could not read during the migration stays in the keyring, and that account asks you to sign in once instead of failing silently
